# feat-027 — live browser pass

## F-01 · **The API's CORS never allowed `PATCH`** — two features were shipping dead

**Severity: high. Found by a browser, and it had been true since feat-001.**

Preferences saved nothing and the interface did not change. The request was not rejected by the
API — it never left the page:

```
%dev.quarkus.http.cors.methods=GET,POST,PUT,DELETE,OPTIONS
%prod.quarkus.http.cors.methods=GET,POST,PUT,DELETE,OPTIONS
```

`PATCH /users/{id}` has existed since feat-001. Nothing had ever called it from a browser until
**feat-024** renamed a member and **feat-027** saved a language — so both features were, at that
moment, shipping a control that could not work.

**Why every test was green.** The API's own tests call the endpoint through RestAssured, where CORS
does not exist. The web project's tests intercept at the fetch layer, where it does not apply.
Two suites, 700+ tests between them, and neither could see it. Only a real browser makes a
preflight.

**Fixed** in both profiles, and guarded: `CorsMethodCoverageTest` reads the JAX-RS annotations on
the resource classes and the configured allow-list, and fails when the second does not cover the
first. Probe — removing `PATCH` again:

```
CORS for the 'dev' profile allows [POST, DELETE, GET, PUT, OPTIONS]
but the API exposes [GET, POST, PUT, PATCH, DELETE]
— a method missing here is unreachable from any browser
```

It is a plain unit test, no container, so it cannot be skipped for being slow.

**Note on feat-024.** Its own live pass measured the members grid entering edit and never confirmed
a save, so it did not catch this. That is a gap in how that pass was run, recorded rather than
quietly fixed: *a live pass on an editable surface must complete one write.*

## What was verified after the fix

| Check | Result |
|---|---|
| CORS preflight | `access-control-allow-methods: GET,POST,PUT,PATCH,DELETE,OPTIONS` |
| Preferences opens from the branding bar | panel titled **Preferences**, language at `en` |
| Language options | **English** and **Português**, each written in its own language |
| Choosing Português | interface changed **without a reload**: Preferences → *Preferências*, Help → *Ajuda*, Sign out → *Sair*; the panel's own title followed |
| Persisted | `app_user.locale_preference = 'pt'` in the database |
| Help | product, release, workspace and signed-in member; **zero `<a>` elements** — nothing this product cannot honour |
