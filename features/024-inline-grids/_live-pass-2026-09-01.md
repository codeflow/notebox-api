## F-01 · Entering edit re-flowed the columns — **again, in three more grids**

The type's field grid, measured before anything else was checked:

| | Name | Type | Visible | Secret | Constraints | Actions |
|---|---|---|---|---|---|---|
| read state | **298** | 243 | 74 | 74 | 271 | 193 |
| in edit, before the fix | **417** | 188 | 74 | 74 | 210 | 190 |
| in edit, after the fix | **298** | 243 | 74 | 74 | 271 | 193 |

**This is feat-023's T-09 defect, inherited.** That pass found it on the records grid and fixed it
*inside* `RecordsGrid` — so the next three grids were born with it. The same shape as a severity
icon asked for "pra cada tipo de alerta" and delivered to one dialog out of nine: a thing that
belongs to a class, solved for one member of it.

The fix is `components/grids/useFrozenColumns.tsx`, extracted from `RecordsGrid` and now used by
all four editable grids. It also carries feat-023's audit finding F-03 with it: the widths are
released **only on a successful save**, because a rejected one keeps the row in edit.

## The rules, checked where they matter

- **C-03 / B-3** — the members row offers **one** control, the name. No control anywhere carries
  the role column's name, because `UserResource` has no endpoint that changes a role.
- **B-3b** — the live-pass account is the signed-in member, and its own row rendered **no status
  control**, exactly as designed.
- **B-1** — every read-only cell carried its localized hint, read straight off the DOM:
  *"The email address is the sign-in identity and is not edited here"*, *"A role is set when the
  member is provisioned and is not edited here"*, *"Counted from the items in this group — not
  edited"*.
- **B-5** — renaming a group opened **no dialog** (`.af-dialogOverlay` count 0); it edits the row.
  Creating still uses its dialog, and creating "Infra" through it worked.
