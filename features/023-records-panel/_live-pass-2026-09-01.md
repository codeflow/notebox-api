## F-01 · A row edit erased the record's hidden fields — **data loss, found on live data**

**Severity: high.** Confirmed by reading the database before and after.

`RecordsGrid` built its PUT body from the row it had listed. The write is replace-not-patch, so
anything absent from the body is deleted. `rowReplaceInput` was written for exactly this and still
did not prevent it, because of a fact no test in the web project could see:

```java
// AnnotationRecordDto.forListing — the API projects listing values down to the visible fields
if (value != null && field.isVisibleForViewing()) { values.add(...); }
```

The row never *received* the hidden values, so it could not carry them.

**Reproduced.** Record *Revisão de contrato* (type *Reunião de projeto*), whose `Notas` field is
`visibleForViewing: false`:

| Step | `Notas` in the database |
|---|---|
| seeded | `<p>nota que nao aparece no grid</p>` |
| edited `Participantes` 42 → 16 in the row, confirmed | **row gone — the value was deleted** |
| after the fix, edited 16 → 21, confirmed | `<p>nota que nao aparece no grid</p>` — intact |

**Fix.** The row's confirm re-reads the record (`annotationRecordsClient.get`) and overlays the
draft onto the *detail* payload. INV-E2 holds: it counts update requests, and this adds a read.

**The test was lying, and that is the more important half.** `RecordsGrid.test.tsx` asserted the
hidden field survived — using a fixture whose *listing* row carried a hidden value, which the real
listing never sends. The fixture has been split into `row()` (mirrors `forListing`) and `detail()`
(mirrors `from`), and the probe now kills the real defect:

```
--- PROBE T-09: build the body from the listed row
   × sends ONE request that keeps the fields the row does not show
```

## F-02 · Entering edit made every column jump sideways

`<input type="number">` carries a preferred width of ~260px. In an auto-layout table the column
sizes to it, so clicking the edit icon re-flowed the whole grid.

| | Name | Assunto | Participantes | Group | Actions |
|---|---|---|---|---|---|
| read state | 334 | 297 | **171** | 153 | 198 |
| in edit (before the fix) | 296 | 273 | **273** | 135 | 175 |
| in edit (after the fix) | 334 | 297 | **171** | 153 | 198 |

**Fix, in two parts:** the number editor is capped at `6rem`, and the grid freezes the column
widths it measured on entering edit (`<colgroup>` + `table-layout: fixed`, for the duration of the
edit only). Controls now sit under their headers: text input at x=613 under a header at x=606,
number at x=911 under x=903 — the 7px is the cell's own padding.
